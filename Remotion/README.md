# Vibe Copy — Telegram Screencast v9 (Social Fill)

## Что изменилось по сравнению с v8

- Основная композиция `VibeCopySocialFill` **1080 × 1920** (9:16), 30 FPS.
- Telegram заполняет **всю ширину кадра**: боковой размытый фон из v8 больше не существует.
- Вместо увеличения готового видео используется **адаптивная высота внутреннего макета**: 591 × 1050,67 условных px, масштаб 1080/591.
- Системная строка iPhone (часы, LTE, батарея, возврат в Telegram) **вообще не рисуется** в Social Fill; старые часы не перекрываются наклейкой.
- Заголовок чата находится у верхнего края, строка ввода — у нижнего. Переписка работает между ними.
- Галерея остаётся со специальным блоком камеры высотой в две ячейки, двумя открытиями и выбором оригинала / референса.
- Экран просмотра результата адаптирован под меньшую высоту. Финальный экран профиля с `@vibecopy_bot` смещён вверх, чтобы ссылка не располагалась у нижнего края под интерфейсом платформы.
- Начало без презентационного экрана: чат → отправка `/start` → приветствие.

## Установка и запуск в VS Code / Git Bash

1. Распакуйте ZIP в папку, в которой находится `package.json`.
2. Откройте папку в VS Code.
3. В терминале выполните:

```bash
npm install
npm run dev -- --no-open
```

4. Откройте http://localhost:3000 и выберите композицию `VibeCopySocialFill` (есть также совместимое имя `VibeCopy1080`).
5. Для экспорта остановите Studio (`Ctrl+C`) и выполните:

```bash
npm run render
```

Результат: `out/CASE_001-social-fill-1080x1920.mp4`.

Рендер использует concurrency=1 и выключенное параллельное кодирование, как в предыдущей версии, чтобы снизить вероятность сбоя FFmpeg под Windows.

### Альтернативный просмотр без Remotion CLI

```bash
npm run preview:frames
```

Откройте `http://127.0.0.1:8088/preview/index.html`. Этот предпросмотр показывает **внутренний макет**. Для итогового кадра 1080×1920 используйте композицию в Remotion.

## Конфигурация

`cases/CASE_001.json` содержит пути к фотографиям, тексты, тайминг и переключатели сцен.

Файлы для замены:
- `public/assets/original.jpg` — исходник;
- `public/assets/reference.jpg` — референс;
- `public/assets/result.png` — результат.

Параметры нового макета:

```json
{
  "ui": {
    "video_layout": "social_fill_1080x1920",
    "show_status_bar": false,
    "social_fill_mode": "adaptive_reflow"
  },
  "show_start_screen": false
}
```

`show_status_bar` в этой композиции всегда отключён; для нативной композиции настройка определяет, рисовать ли системную строку.

После редактирования JSON перед рендером выполните `npm run render`, который автоматически подготовит конфигурацию. Для другого JSON-кейса: `npm run render -- cases/CASE_SHORT.json`.

## Проверка

```bash
npm run check:v9
```

Проверка охватывает длительности конфигураций, обязательные ассеты, отсутствие системной строки в Social Fill, сцены галереи и просмотра результата.

В `qa/storyboard-v9.jpg` сохранены 8 кадров тестовой отрисовки браузером, включая галерею, результат и профиль. Полный MP4 Remotion CLI в этой среде не рендерился; финальную плавность необходимо проверить после локального экспорта.

## Важно о Reels / TikTok

Этот файл имеет реальные размеры 1080×1920 и **не содержит встроенных боковых полос**. Но приложения могут накладывать собственные интерфейсные элементы (кнопки/описание) поверх нижней и правой части кадра. Перед публикацией проверьте безопасную зону CTA в предпросмотре конкретной платформы.

При просмотре 9:16 в стандартной галерее вытянутого iPhone могут оставаться чёрные полосы **сверху и снизу, созданные плеером**; это не поля внутри MP4.
